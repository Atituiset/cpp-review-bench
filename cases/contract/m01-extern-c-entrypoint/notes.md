# m01-extern-c-entrypoint 用例说明（三段式）

## 1. 真实仓形态（这个 case 从哪来）
C/C++ 混合工程里，C++ 模块用 `extern "C"` 导出符号供 C 侧链接调用。C++ TU 内该
函数本地零直接调用——单 TU 静态分析易误报「未使用/死代码」。但它是 C 侧链接入口。

## 2. 为什么契约安全 / 哪里是真缺陷
- **安全点**：`m01_entry` 是 C 侧 `c_caller` 的链接入口——非死代码。
- **真缺陷（混入）**：`m01_entry` 内 `buf[n]` 索引，n 未校验，n 超界越界读
  （cwe-125）。真实缺陷。

## 3. 各工具可能误判方式
- CSA / CppCheck / clang-tidy：可能把 m01_entry 误报为「未使用函数」；对 buf[n]
  越界可能因 n 跨语言来源不敏感漏报。
- cooddy：若做跨语言链接分析，应能不误报死代码且查到越界——对照。
