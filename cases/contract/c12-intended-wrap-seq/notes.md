# c12-intended-wrap-seq 用例说明（三段式）

## 1. 真实仓形态（这个 case 从哪来）
协议栈（RLC/PDCP）的序号按 8/16 位**模回绕**是标准设计（如 `seq = (seq+1) % 256`）。
评审者/工具看到 `seq++` 或 `seq + 1` 容易误报 cwe-190 整数回绕——但回绕是契约行为。

## 2. 为什么契约安全 / 哪里是真缺陷
- **安全点**：`seq_next` 的 `seq+1` 回绕是预期（序号模 256），下游按模使用——安全。
- **真缺陷（混入）**：`ring_get` 的环形缓冲容量仅 `RING_SIZE=64` 项，而
  `pos = (uint8_t)(seq + idx)` 是模 256 序号空间的值（0..255），未按容量取模就
  直接索引。`seq+idx` 落在 [64,255] 时越界读（cwe-125），如 seq=100、idx=10 →
  pos=110，读取 ring[110] 超出 64 项缓冲。这是真实缺陷，与"意图回绕"区分。

## 3. 各工具可能误判方式
- CSA / CppCheck：可能把 `seq+1` 回绕误报 cwe-190（看不到回绕契约）；对 `pos` 越界
  也可能因符号/回绕不敏感漏报。
- cooddy：若识别"回绕即意图"的契约标注，不误报 seq_next；用于对照精度。
