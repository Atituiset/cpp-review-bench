# m03-c-guard-cpp-deref 用例说明（三段式）

## 1. 真实仓形态（这个 case 从哪来）
C/C++ 混合工程：C 侧入口判空后调用 C++ 引擎方法解引用（跨语言边界）。契约：C 侧
判空守护，C++ 引擎内部假设非空。工具可能按「C++ 解引用未见显式判空」误报 cwe-476。

## 2. 为什么契约安全 / 哪里是真缺陷
- **安全点**：`c_entry` 先 `if (e == NULL) return;` 判空，再跨语言调引擎——安全。
- **真缺陷（混入）**：`Engine::process` 内 `buf[idx]` 索引未与 `len` 约束，idx>=len
  越界读（cwe-125）。真实缺陷——跨语言调用不豁免 C++ 内部越界。

## 3. 各工具可能误判方式
- CSA / CppCheck / clang-tidy：可能把跨语言解引用误报 cwe-476（看不到 C 侧判空）；
  对 `buf[idx]` 越界可能因跨语言/len 未比较漏报。
- cooddy：若做跨语言过程间分析，应能不误报 cwe-476 且查到越界——对照。
