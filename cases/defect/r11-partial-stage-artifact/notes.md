# r11-partial-stage-artifact 用例说明（三段式）

## 1. 真实仓形态
代码评审通过了一棵树（有边界检查），但实际提交/编译进镜像的是另一棵树（漏检查）——
评审与集成的「树不一致」缺陷，传统单 TU SA 看不到（它只看提交的树）。

## 2. 真缺陷在哪
- **真缺陷**：提交版（STAGED_TREE=0）`r11_get` 漏掉 `if (idx>=16u)` 检查，`arr[idx]`
  越界——评审过的树与提交的树不一致（build/集成类缺陷）。评审版（STAGED_TREE=1）
  分支中的检查叙事保留，作为「评审通过的那棵树」的载体。
- **安全点**：`r11_get_ok` 位于实际编译的活动树中，带 `if (idx >= 16u) return 0;`
  边界检查，`arr[idx]` 恒在界内——报越界读（cwe-125）属误报。注意原安全点锚点
  位于 STAGED_TREE=0 下的死分支，预处理后不存在，FP 探针不可达；因此安全点
  改锚到活动树中的 r11_get_ok。

## 3. 各工具误判方式
- 此类缺陷传统 SA 难查（它只看提交的树，恰好是漏检查的版本，可能不报越界因为 idx
  来源不明）。
- cooddy/CodeQL：若做「评审树 vs 提交树」比对或符号执行探 idx 范围，可能查到——对照。
- 这是 Agent Viewer 要补的「集成期一致性审查」能力。
