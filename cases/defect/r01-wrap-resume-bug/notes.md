# r01-wrap-resume-bug 用例说明（三段式）

## 1. 真实仓形态（这个 case 从哪来）
RLC/PDCP 发送窗口维护模 256 的发送序号（`tx_next`/`ack`），窗口缓冲 `win` 按
WIN_SIZE（64）项环形分配——序号空间大于窗口容量是协议常态（窗口受流量控制限制，
远小于序号空间的一半）。超时恢复时基于 `(tx_next - ack)` 算重传起点，再从 `win`
取回缓存负载。

## 2. 真缺陷在哪 / 安全点为什么安全
- **真缺陷**：`resume_point` 把模 256 序号空间的原始序号 `resume`（0..255）直接当
  `win` 下标，未按 WIN_SIZE 取模；`resume >= 64` 时越界读（cwe-125）。陷阱点在于
  `(tx_next - ack)` 的模 256 差值本身是**对的**——回绕语义正确，错的是恢复点索引进
  窗口缓冲前少了取模。评审若在差值回绕上"找茬"反而跑偏。
- **安全点**：`rlc_fill` 以 `sn % WIN_SIZE` 取模索引 `win`，索引恒在 0..63 界内——
  安全，非缺陷。

## 3. 各工具可能误判方式
- CSA / CppCheck / clang-tidy：`uint8_t` 索引 64 项数组，需要值域分析才能判定越界，
  可能漏报；也可能把取模后的 `rlc_fill` 误报为越界。
- cooddy：符号执行+约束求解应能推出 resume 值域超出 win 容量——对照其相对传统 SA
  的精度。
